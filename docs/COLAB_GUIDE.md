# How to run the project in Google Colab (v3: Phases 1–4)

Notebook: <https://colab.research.google.com/github/lowkey2556/cosmic-events/blob/main/notebooks/cosmic_colab.ipynb>
(generated by `scripts/build_notebook.py`; every cell is a thin call to `run.py`).

**Just want the results?** Open the notebook, scroll to the last section **▶️ RESULTS — start here** and run its cells
top to bottom. It mounts Drive, reads the saved files (nothing is recomputed) and ends with `ALL RESULTS SHOWN`, or
with a list of what has not been produced yet followed by `RESULTS INCOMPLETE`.

## 2. Execution order

Run the cells in this order (the notebook already has them in this order). Steps joined with `+` share one Spark
session. Every `run.py` step writes its wall time to `outputs/step_timings.csv`, and `report` copies those times into
`DATA_FLOW.txt`.

| # | Cell / command | Needs the stack? | What it makes |
|---|---|---|---|
| 0 | **SETUP** (mount, clone/pull, Python envs, path check) | no | `/content/cosmic`, `/content/cosmic_py` |
| 1 | `ztf_download` (+ `ztf_select` only if no selection is saved) | no | nothing new when all 117 files are verified: **no re-download** |
| 2 | `ztf_audit`, optional `candidates` | no | `ztf_audit_*.csv`; `aavso_candidate_stars.csv` |
| 3 | `audit` | no | `audit_*.csv` (50 MB check) |
| 4 | `install_stack.sh`, `start_stack.sh`, env cell, smoke tests 1–5 | — | HDFS, YARN, Hive metastore up; 5 × PASS |
| 5 | `architecture` | no | `architecture.png/.svg/.dot` |
| 6 | `ingest+preprocess+score+features` | yes | Hive `observations_raw`, `obs_clean`, `observer_scores`, `star_features` |
| 7 | `ztf_ingest+ztf_clean+ztf_label` | yes | Hive `ztf_lightcurves_raw`, `ztf_lightcurves_clean` (+ Drive copy), `ztf_labels` |
| 8 | `windows+ztf_windows+akval` | yes | Hive window tables, `work/windows_seq.npz`, `work/ztf_windows_seq.npz`, `ak_validation_summary.csv` |
| 9 | `cluster+classify` | yes | K-Means tables; `work/predictions_ml.csv`, Hive `ml_predictions` |
| 10 | `rganet` | no (GPU) | `work/models/*.pt`, `predictions_rganet.csv`, `rganet_runs.csv`, `rganet_grid.csv`, `rganet_pretraining.csv` |
| 11 | `infer`, then `compare` | yes / no | Hive `window_predictions`; every comparison table and `COMPARISON.md` |
| 12 | `dashboard`, then `report` | yes / no | `dashboard_data/`; `outputs/figures/` (13 items), captions, `DATA_FLOW.txt` |
| 13 | optional: `scalability`, then `report` again | yes | `scalability.csv`, `scalability_runs.csv` |
| 14 | **▶️ RESULTS — start here** | no | shows everything above; ends with `ALL RESULTS SHOWN` |

**Fresh machine:** a Spark step whose input tables are missing first runs the steps that make them
(`src/cosmic/pipeline.py`), e.g. `akval` on a new VM runs `ingest → preprocess → score → ztf_clean` first. `ztf_clean`
restores the cleaned table from `v3_5GB/clean/` when it was made from the same raw files (checked by the MD5 manifest),
so the 8.5 GB clean is done once.

**Disconnect during `rganet`:** run the cell again. Pre-trained encoders, grid points and finished (variant, seed) runs
are reused from `work/`.

## 4. When Colab disconnects or resets

**Lost:** the stack, HDFS and the Hive tables, the clone. **Kept in Drive:** all of `cosmic_roja/` (raw ZTF, the
cleaned ZTF copy, `work/`, `outputs/`).

| You want | Run |
|---|---|
| only the results | the **RESULTS** cells (they mount Drive themselves) |
| `rganet`, `compare` or `report` again | SETUP, then those `run.py` steps: they need no stack (they read `v3_5GB/work/`) |
| any Spark step | SETUP, stack cells, then the step; missing tables are rebuilt automatically (§2) |
| kernel restart only | SETUP, `bash setup/start_stack.sh`, the env cell, then continue |

## 5. Common errors and fixes

| Problem | Fix |
|---|---|
| `FileNotFoundError: The data folder does not exist` | Drive not mounted or a wrong `PROJECT_ROOT`; re-run SETUP |
| `No VizieR server answered` in `candidates`/`ztf_label` | VSX now falls back to NASA HEASARC (`aavsovsx`) automatically. If HEASARC is down too, wait and re-run; per-field VSX results are cached in `v3_5GB/work/ztf_vsx/` |
| `No downloaded ZTF files (MANIFEST.csv)` | run `ztf_download` (it only fetches what is missing) |
| `The ZTF files lack expected columns` | a file is not a ZTF DR light-curve file; check `ztf_raw/` |
| `ztf_windows_seq.npz is missing` in `rganet` | run `windows+ztf_windows` first (pre-training needs it) |
| Out of memory in `ztf_clean` (`Java heap space`, container killed) | High-RAM runtime if offered; or `--set spark.shuffle_partitions=96` |
| `CUDA out of memory` | `!python run.py rganet --data real --set rganet.batch_size=32 --set rganet.pretrain_batch_size=64` |
| `Table or view not found` | should rebuild automatically; if not, run the earlier Spark steps in order (§2) |
| `RESULTS INCOMPLETE` | the line above it names the missing files and the step that makes each one |
| PNG export failed | HTML and JSON are still saved; see `outputs/figures/figure_export_log.csv` |

## 8. Local end-to-end check (for developers; no Colab)

`scripts/local_e2e.sh` runs every step on synthetic AAVSO and synthetic ZTF data with Spark in local mode
(`--set spark.master=local[2] --set hdfs.namenode=file:///…`): an embedded Hive metastore, a local folder in place of
HDFS, offline VSX and field-centre files. Java 8, 11 or 17 is required (Spark 3.5 + Arrow fail on Java 21). Outputs go
to `synthetic_run/` only. Unit tests: `python -m pytest -q tests`.
